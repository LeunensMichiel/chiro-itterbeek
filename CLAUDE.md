# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Website of Chiro Itterbeek (Belgian youth movement, Dutch-language content). Next.js 16 App Router as a **fully static export**, React 19, TypeScript, Tailwind CSS v4, content from Contentful, hosted on Netlify. Next.js 16 differs from older versions: check `node_modules/next/dist/docs/` before using framework APIs.

## Commands

```sh
npm run dev         # dev server, localhost:3000
npm run build       # static export into ./out (fetches all Contentful content)
npm run start       # serve ./out
npm run lint        # ESLint (next core-web-vitals + typescript)
npm run typecheck   # tsc --noEmit
npm run format      # Prettier, also sorts Tailwind classes
```

There is no test suite; verify with `lint`, `typecheck` and `build`. Node 24 (`.nvmrc`). `dev` and `build` need a `.env` with `CONTENTFUL_SPACE_ID`, `CONTENTFUL_ACCESS_TOKEN`, `NEXT_PUBLIC_MAPBOX_TOKEN` (optional `CONTENTFUL_HOST=preview.contentful.com`).

## Architecture

**Static export, no server.** `next.config.ts` sets `output: "export"` and `trailingSlash: true` (Netlify serves `/path/`). No server actions, route handlers with dynamic data, middleware or runtime image optimization. Every dynamic route sets `dynamicParams = false` and builds its pages in `generateStaticParams`. Content changes reach the site only through a rebuild, triggered by a Contentful → Netlify build hook.

**Content layer** (`src/lib/contentful.ts`): one typed fetcher per content type (`getPosts`, `getAlbums`, …), wrapped in `once()` so each type is fetched once per build. Fetchers map SDK entries to small plain domain types (`Post`, `AgeGroup`, `CmsImage`, …); components never touch Contentful SDK shapes. Add new content the same way.

**Jokonta / Allegro (the core concept).** There are two chiros: Jokonta (boys) and Allegro (girls); content can also be for both (`"itterbeek"`, labelled "Algemeen"). Types and helpers are in `src/lib/chiro.ts` (`Chiro`, `Audience`, `isFor`). The visitor's choice and the light/dark theme are stored in localStorage and applied as `data-chiro` (`jokonta | allegro | none`) and `data-theme` on `<html>` by an inline `preferencesScript` before first paint. The static HTML contains the content for **both** chiros, and CSS decides what shows:
- Tailwind custom variants in `src/app/globals.css`: `jokonta:`, `allegro:`, `unchosen:`, `dark:`.
- `<OnlyFor chiro="jokonta|allegro|unchosen|chosen">` (`src/components/only-for.tsx`) wraps per-chiro content with `display: contents`.
- Client code reads and changes the preferences with `useChiro`, `useColorMode`, `setChiro`, `toggleChiro` and `toggleColorMode` in `src/lib/use-preferences.ts` (a `MutationObserver` on `<html>`; the hooks return `null` during SSR).

Don't branch on the chosen chiro during render to decide what HTML exists. Render both and hide with the variants, or the page flashes after load. The localStorage keys/values match the old Gatsby site so returning visitors keep their choice; don't rename them.

**Dates**: date-dependent UI (calendar month, leiding ages) uses `useToday(buildDay)` (`src/lib/use-today.ts`). It renders the build date in static HTML, then switches to the visitor's date on hydration.

**Pagination**: list pages use optional catch-all `[[...page]]` routes. Page 1 lives at the base path, page n at `base/n/` (`src/lib/pagination.ts`: `pageParams`, `parsePage`, `PER_PAGE`). `/nieuws/[[...slug]]` serves both the paginated list and individual posts, so a post slug may not be purely numeric (the build throws).

**Images**: Contentful images go through `next/image` with a custom loader (`src/lib/contentful-image-loader.ts`) that resizes via Contentful's Images API. Allowed qualities are `80` and `90` only.

**Styling**: design tokens (colors incl. `jokonta`/`allegro`/`accent`, font sizes) are in `src/app/globals.css` `@theme`. Breakpoints are custom and **desktop-first**: `mobile-s` 375, `mobile` 768, `tablet` 1025, `laptop` 1281. Use `max-tablet:`, `max-mobile:` etc. Default Tailwind breakpoints are disabled. Class names are combined with `cx` from `src/lib/cx.ts`.

**Icons** in `src/components/icons/` are generated by `@svgr/cli` and excluded from Prettier; regenerate them rather than hand-editing. Other SVGs/images in `src/assets/` are imported as static assets.

## Deployment gotchas

- Netlify config is in `netlify.toml` (build, security headers, legacy Gatsby redirects).
- Contact forms use Netlify Forms. The visible form depends on the chosen chiro, so `public/__forms.html` declares both forms for Netlify's deploy-time detection. **Keep its field names in sync with `src/components/contact/contact-form.tsx`.**

## Code style

Prettier: no semicolons, `arrowParens: "avoid"`, Tailwind class sorting. Imports use the `@/` alias for `src/`.
